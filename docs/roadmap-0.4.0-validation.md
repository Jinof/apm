# Roadmap 0.4.0 相册首页与滚动验收

Android APM 0.4.0（versionCode 15），2026-11-21。

## 照片数量与日期

首页顶部居中显示整个相册中可访问的照片总数。首排上方显示当前照片墙中最新一张的拍摄日期。日期按设备时区换算。选择热力图范围后，页头保留相册总数，范围摘要显示筛选数量，首排日期取筛选后的第一张照片。[首页截图](assets/roadmap-0.4.0/album-top.png)

页头完全滚出后，顶部的日期随第一张仍可见的照片更新。上一行在屏幕上还剩一部分时，日期仍属于那一行。回到顶部后恢复行内日期。空相册显示“0 张照片”。照片缺少拍摄时间时显示“拍摄时间未记录”。[滚动截图](assets/roadmap-0.4.0/album-scrolled.png)

## 缩略图加载

六列方框先确定尺寸。拖动和惯性滚动期间，已经显示的缩略图继续可见，新进入且未命中缓存的格子先显示底色。停稳后只补当前视口，最多同时执行四次后台读取。离开视口的请求会取消，缓存按照片内容标识、URI 和像素尺寸复用，上限为 16 MiB 与应用堆上限八分之一中的较小值。[快速滑动中的照片框](assets/roadmap-0.4.0/album-scrolling.png)

使用受控缩略图读取器连续跨过两段各约 20 行的距离。测试检查了中途格子已有正方形边界、经过的测试照片没有发起读取、停稳后目的格出现图像且边界一致，以及返回首张时复用了缓存。另一项测试让已经取消的旧请求迟到返回，检查同一 URI 对应的新照片仍显示正确图像。

在 600 张测试图的实际照片墙上，停稳时顶部第一张为只露出部分画面的 `RM040-402.jpg`，悬浮日期与该照片的拍摄日期 2026-08-12 一致。核对界面节点边界和截图像素，全部 78 个与视口相交的照片框均已显示图像，包括底部只露出 26 像素的一行。

## 快速滑动实测

在同一台 API 35、1080 × 2400 的 ARM64 模拟器上，两个版本使用同一批 600 张 JPEG 和同一份相册目录。每轮重启进程，首屏显示两秒后清零帧统计，连续向上拨动四次以向下浏览。每次手势用时 120 ms，间隔 120 ms。每版先预热一轮，再运行五轮，表中取各项指标的五轮中位数。数据来自 Android 的 `dumpsys gfxinfo`。

| 版本 | 帧耗时 P50 | 帧耗时 P90 | 帧耗时 P95 | 系统标记的卡顿帧占比 |
|---|---:|---:|---:|---:|
| 0.3.0（14） | 44 ms | 65 ms | 85 ms | 24.68% |
| 0.4.0（15） | 23 ms | 36 ms | 48 ms | 9.42% |
