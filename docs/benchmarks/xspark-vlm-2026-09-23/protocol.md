# 测试协议（运行候选模型前固定）

- 场景：APM 单张照片标注，单并发；所有实测请求由 xspark 本机发出。生产 Qwen 服务与 IndexTTS 保持驻留，候选模型逐个在回环端口 8096 启停，不改变 new-api 默认渠道。
- 原图由 imagegen 内置工具生成，原件保留。检查实际图像后确定 `ground-truth.json`，不把生成提示词中的要求直接当作正确答案。
- 请求图统一为最长边 1024、JPEG 质量 82，与 Android 的主请求尺寸策略一致。Pillow 与 Android 编码器不保证逐字节相同；所有候选收到的 JPEG 字节完全相同，SHA-256 记录在 `input-manifest.json`。
- 完整标注使用 Android `photo-annotation-zh-v7` 提示词；`prepare_inputs.py` 重建相同字段及长度限制的 JSON Schema。固定 temperature=0、seed=23、关闭思考，最多输出 1536 token。APM 当前不主动传 temperature，本基准固定它以便比较。
- 各配置先执行一次不计入中位数的预热请求，然后执行三次完整标注。标注后执行一次 23 项视觉问答，限制 640 输出 token。问答用于效果评估，不用于稳定延迟排名。
- 每个请求使用独立的 `cache_salt` 和图片 UUID，避免同一图片的提示词、图像处理或编码缓存命中；候选服务另外关闭图像处理缓存。
- 标注请求启用流式返回，仅为测量首字时间；原 App 使用非流式返回。两者都必须等完整 JSON 才能落库。
- 时间从 HTTP 请求发出前开始计时。首字延迟是第一个非空正文 delta 到达的时间；总耗时截至流结束；解码速率为 `(completion_tokens - 1) / (最后正文时间 - 首字时间)`。单个 SSE delta 不等同于单个 token，因此使用服务返回的 usage token 数。
- 报告三次测量的中位数与范围，不从三个样本估算 p95。输出长度、首字、解码速度与总耗时分别列出，避免把“少输出”误当作“算得更快”。
- 有效结果须满足 HTTP 成功、流正常结束、`finish_reason=stop`、可解析 JSON、Schema 通过、没有思考正文。失败、截断或启动错误保留原始记录，不能作为快速成功结果。
- 视觉问答每项一分，共 23 分：数量、颜色、空间位置、中文菜单、数字价格、英文封面、海景/天空/昼夜、人物动物数量与无法确定的具体城市。字符串同义词规则提前固定在 `ground-truth.json` 和 `benchmark.py`。
- 复核时发现“勺子在杯子下方”与场景坐标的“前方”均正确，已在 `scoring-review.json` 记录统一修正；所有模型使用同一规则，原始自动得分不覆盖。完整标注的八类核心物体按实际物体计数，碗/盘、书籍/笔记本等可接受近义名称统一合并。
- 一张合成图和一次问答只提供该样本证据；不代表真实图库、复杂遮挡、低清照片、长视频或模型总体能力。完整标注还需人工复核其物体遗漏与无依据描述，JSON 合法不等于内容正确。
- 模型加载、下载、首次内核编译与稳定请求耗时分开记录；生产基线已经常驻，所谓“预热”只表示本基准的首张图，不等于冷启动。
- 推理优化对照保留同一份 Qwen3.8-27B FP8 权重，单独启用 `FULL_DECODE_ONLY` CUDA Graph，不启用 torch.compile 或投机解码。其他候选使用同一 Graph、16K 上下文、单并发、2 GiB KV 缓存配置；MoE 的额外内核参数如实记录在 `launch.json`。

## 图像生成提示词

使用内置 imagegen。生成一张 3:2 的写实海边咖啡馆桌面照片，阴天白昼，桌上有一只白碗及三个红苹果、两根黄香蕉、一只把手朝右的蓝杯、一册橙色笔记本、黑屏黑色手机和杯前的银色勺子。笔记本封面为 `APM 2026`，菜单正面为 `海边咖啡`、`LATTE ¥28`、`CAKE ¥18`。要求物体清晰分离、文字可读、没有人物和动物。完整生成提示词见 `image-prompt.txt`。
