# APM 0.2.0

2026-11-11，Android 版本 **0.2.0（versionCode 13）**。

## 更新

- 每个 API 独立设置合并张数，范围 **1–8，默认 1 张**。旧配置缺少该字段时同样读取为 1，不自动开启合图。
- 选择 2–8 张后，多张照片按原始比例生成一张编号缩略图，一次 API 请求分别识别，结果按编号保存到各张原照片。
- 并发度仍控制同时发送的请求数，范围 1–8、默认 8；与合并张数分开设置。任务卡片区分请求并发、正在处理的照片数和完成数。
- 支持不足一组的尾批及乱序返回。结果缺失、编号重复或任一标注不合格时，整组保留旧标注，其他组继续；取消后不再派发，也不写入迟到结果。
- “测试连接”按当前合并张数生成测试图片，验证相应协议。已有同模型的受支持标注继续跳过，修改合并数量不会强制重做。

合并为 1 张时保留原来的单张协议。合图减少每张照片的可用像素，细字、小物体和空间关系可能更难识别；一次返回多张完整标注也可能需要更长等待。

xspark 的 Qwen3.6 经 new-api 实测，一张 8 格生成合图完整返回耗时 **24.124 秒**，8 个编号、OCR、颜色及圆形数量均正确；其中两格的排列属性有误。该测试验证协议和对应关系，不是合图与单张的速度对照。完整结果见 [0.2.0 验收记录](roadmap-0.2.0-validation.md)。

## 验证与升级

- Promise、23 项 Python、54 项 JVM 和 47 项模拟器测试通过；Android lint 0 错误、7 条警告、2 条信息。
- 发布时复核功能代码未变，APK 与已测试原件逐字节一致，签名、版本和 API-only 检查通过，沿用同一份验收 APK。
- 包名仍为 `com.jinof.apm`，继续使用原 debug 签名；SQLite 保持 schema 8，Python CLI 保持 0.0.5。
- 已对小米 23127PN0CC 执行 `adb install -r`，从 0.1.0（12）更新到 0.2.0（13）。安装前后数据库、加密配置等 11 个私有文件的 SHA-256 一致，权限及首次安装时间一致，已安装 APK 与发布附件相同。核对时未自动启动应用，也未导出私有文件内容。
- 升级保留照片、历史标注和 API 配置。合并张数默认 1，现有并发配置保留；首次启动按原规则清空临时标注选择。
