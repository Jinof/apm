# Roadmap 0.3.0 UI 优化验收

Android APM 0.3.0（versionCode 14），验收日期 2026-11-21。

## 启动停顿

旧版在 `MainActivity.onCreate` 的主线程上打开 SQLite 并清空本次会话的选择。`onCreate` 和首次 `onResume` 又分别提交了相同的目录读取。读取完成时，Compose 一次性替换启动屏，在主线程重新排序、按天分组并布局首页。分页器还同时布局相邻页的全年热力图。加载环与这些工作共用主线程，切换时画面停在上一帧。

新版用原生启动视图显示文案，加载环在渲染线程旋转。后台工作线程初始化选择并读取一次目录，搜索建议复用已解码的标注。首页直接使用 SQLite 返回的拍摄时间顺序，按屏幕宽度请求缩略图。相册首帧提交后，启动屏随实际绘制帧淡出。

同一台 API 35、1080 × 2400 的 ARM64 模拟器分别安装原交付版和新版。每种状态先启动一次，再停止应用进程、冷启动五次取中位数。首窗耗时取 `am start -W` 的 `TotalTime`。最慢帧取启动窗口内 `gfxinfo framestats` 的 `FrameCompleted − IntendedVsync` 最大值，再取五次中位数。

| 本地相册 | 0.2.0 首窗 | 0.3.0 首窗 | 0.2.0 最慢帧 | 0.3.0 最慢帧 |
|---|---:|---:|---:|---:|
| 空相册 | 630 ms | 370 ms | 873 ms | 234 ms |
| 96 张测试图，其中 48 张已有标注 | 596 ms | 429 ms | 724 ms | 567 ms |

逐帧对比有照片时的原始录屏，加载环在照片墙出现前持续改变角度。抽取淡出的连续帧，照片墙从约 4% 可见逐步增加到 99%，中间可见 15%、31%、45%、60%、73%、85%、94% 的画面。以下视频截取了本次模拟器启动的实际画面。[启动录屏](assets/roadmap-0.3.0/startup.mp4)

## 相册与 Agent

- 从不同拍摄日取七张照片，断言前六张同排、第七张在下一行左端。搜索按钮的中心与照片墙垂直中心对齐。热力图的日期筛选和左边缘手势继续可用。[相册截图](assets/roadmap-0.3.0/album.png)
- 在照片墙打开搜索，输入真实测试标注中的关键词，点结果进入原图查看器。退出查看器后仍可查看搜索结果，再按系统返回键会回到原来的照片墙位置。
- Agent 页按“选择照片”“标注所选”“开始全量标注”排列，任务进度在同一页显示。空选择时可选图，所选标注按钮显示 0 并禁用。回归覆盖单张、并发、合图、失败保留旧标注及配置切换。[Agent 截图](assets/roadmap-0.3.0/agent.png)
- 在实际屏幕坐标上分别点击同一张六列小图的中央和右下角绿勾，分别打开原图查看器和该图的标注详情。点 Agent 页的“选择照片”会打开 Android 系统选图器，取消后所选数量仍为 0。
